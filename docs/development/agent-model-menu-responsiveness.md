# Agent 模型菜单响应优化

日期：2026-11-22。范围：当前工作树的模型菜单和模型列表缓存。

## 原因与调整

权限菜单直接显示本地浮层；原模型菜单使用带渐入动画的 Popover，并在打开时才获取模型能力。内置 Pi 的模型发现涉及 runtime 启动，首次打开或缓存失效时，可选列表需要等待能力请求。

- 模型菜单采用与权限菜单相同的直接展开方式，保留外部点击、Escape、窗口缩放定位和两个菜单互斥。
- Composer 就绪后预取模型能力，沿用现有五分钟缓存及并发请求合并。
- 请求尚未返回时，先使用 readiness 中已经确认启用的模型 ID；返回后补充名称和思考档位。能力请求失败不阻止选择已配置模型，已确认的空列表仍保持为空。
- 保留原来的模型选择和思考档位校验；菜单内部的下拉选项不传送到外部，避免点击选项被当作菜单外点击。

## 验证

- 新回归在修复前复现：故意挂起能力请求后，已配置模型无法选择。
- 设置 store、Agent UI 相关单测 24 项通过；`npm run verify:agent` 通过。
- Desktop 源码及测试类型检查、定向 ESLint、production build 通过。
- Electron 使用真实长文档、42 个候选和挂起的能力请求：能立即选择模型，返回后能设置思考强度；连续打开五次、与权限菜单切换只触发一次能力请求。
- 一次本机测量：模型菜单首次约 13 ms，权限菜单约 13 ms，后续五次约 10–15 ms。计时为 pointerdown 至完整浮层可见的渲染帧，用于本机相对比较，不代表跨设备性能承诺。
- 无配置时的设置入口、Escape 和外部点击另行验证。

扩大运行 `agent-workspace-pane.spec.ts` 时，有四个既有场景失败，失败点不在本次模型菜单改动的操作上：Agent 设置页中已不存在的字号输入、旧 Element Plus tooltip、旧外部 CLI 配置流程、标签栏与 Agent 标题栏阴影一致性。未修改这些断言、未跳过它们，也不将完整套件描述为通过；本次结论限定为模型菜单定向回归。当前内置 Pi 设置入口另有实际 Electron 覆盖。
